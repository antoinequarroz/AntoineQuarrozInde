# AQ-059 — Préflight Supabase reproductible

## Critères d'acceptation

- [x] Une base Supabase locale propre rejoue `schema.sql` puis toutes les migrations versionnées sans erreur.
- [x] Des tests pgTAP vérifient RLS, les droits des tables serveur uniquement, la fonction de paiement atomique et les contraintes d'organisation critiques.
- [x] Le préflight ne contient aucun secret et ne peut appeler ni réinitialiser un projet Supabase distant.
- [ ] Une pull request exécute le préflight sans déployer; un push `main` ne déploie qu'après `quality` et `database` verts.
- [ ] L'échec d'une migration ou d'un test de base bloque le déploiement AQ-058 et laisse la production inchangée.

## Plan ordonné

### 1. Versionner l'environnement local minimal

- **Objectif :** ajouter la CLI Supabase `2.113.0` comme devDependency exacte et un `supabase/config.toml` local sans secret, avec seed désactivé et ports/projet isolés.
- **Fichiers attendus :** `package.json`, `package-lock.json`, `supabase/config.toml`.
- **Autorise :** configuration locale et dépendance de développement épinglée.
- **Interdit :** project ref distant, access token, clé de service, URL/mot de passe de production, modification du schéma métier.
- **Validation :** `npx supabase --version`, `npx supabase --help`, inspection du lockfile.
- **Sécurité / rollback :** configuration locale non exposée; rollback par retrait de la devDependency et du fichier de configuration.

### 2. Construire le replay éphémère

- **Objectif :** ajouter `scripts/ops/test-supabase-migrations.sh`, créer un projet `mktemp`, y copier le socle sous un timestamp antérieur et toutes les migrations, lancer/reset/tester en `--local`, puis nettoyer via `trap`.
- **Fichiers attendus :** `scripts/ops/test-supabase-migrations.sh`, éventuellement `.gitignore` uniquement pour les artefacts locaux réellement produits.
- **Autorise :** fichiers temporaires hors dépôt, Docker local, exclusion de services Supabase inutiles si confirmée par `--help`.
- **Interdit :** `--linked`, `db push`, `migration repair`, `--db-url`, mutation de `supabase/schema.sql` ou des migrations existantes, suppression d'un volume/projet non créé par le script.
- **Validation :** `bash -n`, test statique des commandes interdites et exécution complète locale.
- **Sécurité / rollback :** le nom de projet et le répertoire temporaire sont bornés; le `trap` arrête uniquement cette pile et supprime uniquement ce répertoire validé.

### 3. Tester les invariants PostgreSQL

- **Objectif :** ajouter des tests pgTAP réels pour les tables privées, droits `anon`/`authenticated`, exécution `service_role`, contraintes composites et fonction `record_invoice_payment_atomic` en `security invoker`.
- **Fichiers attendus :** `supabase/tests/database/aq059_security.test.sql` et tests Vitest ciblés du harnais.
- **Autorise :** données et rôles locaux jetables, assertions sur catalogues PostgreSQL et privilèges.
- **Interdit :** données réelles, appels réseau, affaiblissement d'une assertion pour faire passer une politique existante.
- **Validation :** `npx supabase test db --local supabase/tests/database`, puis `npm test -- tests/supabase-preflight.test.ts`.
- **Sécurité / rollback :** aucune migration de production dans cette tâche; toute faiblesse révélée mais hors périmètre bloque le ticket et devient une migration append-only distincte.

### 4. Bloquer la livraison sur le préflight

- **Objectif :** ajouter un job `database` sans secrets à `.github/workflows/ci.yml`, puis faire dépendre `deploy` de `[quality, database]` tout en conservant PR non déployante et E2E post-déploiement.
- **Fichiers attendus :** `.github/workflows/ci.yml`, `package.json`, `tests/supabase-preflight.test.ts`, `docs/operations.md`.
- **Autorise :** cache npm, runner Ubuntu/Docker, timeout dédié et commande npm de préflight.
- **Interdit :** secrets Supabase, mutation distante, migration automatique de production, contournement des jobs AQ-058.
- **Validation :** test statique du graphe, PR GitHub verte, puis livraison réelle `quality + database → deploy → version/health → e2e`.
- **Sécurité / rollback :** retirer `database` de `deploy.needs` restaure AQ-058 sans toucher au VPS ni à Supabase.

### 5. Vérifier et livrer

- **Objectif :** exécuter le préflight réel, la suite complète, TypeScript, build, budgets, revue de sécurité et contrôle de diff; publier via PR puis observer la première livraison ordonnée.
- **Fichiers attendus :** seulement les corrections matérielles strictement liées à AQ-059.
- **Autorise :** corrections du harnais, des tests ou de l'orchestration AQ-059.
- **Interdit :** nouvelle fonctionnalité métier, correction silencieuse du schéma production, déploiement manuel contournant AQ-058.
- **Validation :** `npm run test:db`, `npm test`, `npm run typecheck`, `npm run build`, `npm run quality:budgets`, `git diff --check`, checks GitHub et preuve publique du SHA.
- **Sécurité / rollback :** la production reste inchangée tant que le préflight échoue; rollback applicatif assuré par AQ-058.

## Correspondance

- Isolation et privilèges : tâche 3.

- Preuves de bout en bout : tâche 5.
