# AQ-063 — Parcours prospect vers paiement

## Critères d’acceptation

- Depuis un prospect, l’administrateur peut créer un devis prérempli sans perdre le contexte client.
- Chaque succès indique l’étape atteinte et propose une seule prochaine action pertinente.
- La conversion annonce qu’elle accepte le devis et garantit une seule facture par devis.
- Le paiement final met à jour la facture et l’étape CRM sans rechargement ambigu.
- Un scénario E2E sandbox prouve le parcours complet, les retours arrière et l’absence de doublon.
- Toutes les opérations restent bornées à l’organisation et auditées sans données financières sensibles.

## Plan ordonné

- [ ] **Cartographier le parcours UI réel.** Objectif : relever les entrées, sorties, états vides, confirmations et retours de `/admin/crm`, `/admin/quotes`, `/admin/invoices` et `/admin/payments`. Fichiers attendus : mise à jour de `docs/research/AQ-063.md` et captures de test ignorées par Git. Autorisé : navigation et lectures sandbox ; interdit : mutation de clients réels ou de production. Tests : contrôle manuel desktop/mobile et clavier. Validation : rapport reliant chaque rupture à un critère d’acceptation. Sécurité/rollback : lecture seule, aucun rollback.

- [ ] **Unifier le contexte et la prochaine action.** Objectif : conserver `clientId`, `quoteId` et `invoiceId` dans les liens métier, afficher une progression courte et proposer l’action suivante après succès. Fichiers attendus : pages CRM/devis/factures/paiements et composants admin partagés si justifiés. Autorisé : query params validés et navigation interne ; interdit : dupliquer les données financières côté client ou créer un nouveau store global. Tests : préremplissage, retour CRM, focus, mobile et `aria-live`. Validation : tests Vitest ciblés, typecheck et vérification navigateur. Sécurité/rollback : ignorer tout identifiant non autorisé ; rollback par retrait des liens contextuels.

- [ ] **Rendre les transitions explicites et idempotentes.** Objectif : confirmer l’acceptation implicite avant conversion, verrouiller les doubles soumissions et retourner l’objet existant lors d’une répétition. Fichiers attendus : `app/pages/admin/quotes/index.vue`, `server/api/quotes/convert.post.ts`, utilitaires et tests ciblés. Autorisé : validation serveur, CAS/idempotence et audit ; interdit : affaiblir les transitions de statut ou faire confiance aux totaux envoyés par le navigateur. Tests : double clic, requête répétée, devis d’une autre organisation, erreur compensée. Validation : tests API/unitaires verts. Sécurité/rollback : contraintes d’organisation obligatoires ; comportement actuel récupérable derrière la confirmation UI.

- [ ] **Prouver facture et paiement.** Objectif : vérifier que montants, devise, client et projet restent identiques jusqu’au paiement et que le CRM reflète immédiatement le nouvel état. Fichiers attendus : tests de `recordInvoicePayment`, stores concernés et rafraîchissement CRM. Autorisé : rechargement ciblé des données après mutation ; interdit : recalcul financier côté client ou modification manuelle d’une facture verrouillée. Tests : paiement complet, partiel, doublon, surpaiement, mauvaise devise et multi-tenant. Validation : Vitest et test DB local. Sécurité/rollback : opérations transactionnelles et audit conservés ; aucune suppression automatique de paiement.

- [ ] **Ajouter le scénario E2E sandbox et la porte de livraison.** Objectif : créer un prospect de test traçable, parcourir devis → facture → paiement, vérifier le CRM puis nettoyer uniquement les données du scénario. Fichiers attendus : `e2e/admin.spec.ts`, helpers sandbox et documentation d’exploitation. Autorisé : compte E2E et données préfixées dédiées ; interdit : service role dans le navigateur, secrets dans les logs ou nettoyage par motif large. Tests : exécution locale puis post-déploiement avec `E2E_ADMIN_*` et TOTP. Validation : quality → database → deploy → health/version → E2E. Sécurité/rollback : nettoyage exact par identifiants créés ; un échec bloque la livraison et conserve l’image précédente.

## Hors périmètre

- Automatisation d’envoi sans confirmation humaine.
- Refonte visuelle générale du back-office.
