# Rédiger un guide concret pour le site

Le lecteur est un indépendant, une PME ou une association qui doit prendre une décision numérique. Le sujet vient de la file approuvée, pas d'une définition générale. Nommer dès le début la décision à prendre, les contraintes et les limites de la réponse.

Préparer une courte matrice : affirmation, source primaire, date de lecture, portée et réserve. Relire réellement les sources pendant le passage du jour. Les URL du brief sont des points de départ, pas une validation factuelle anticipée. Garder au moins deux sources distinctes accessibles. Les expériences personnelles doivent être attestées par le site, le code ou une preuve autorisée ; les scénarios inventés portent la mention « exemple fictif ».

Construire le Markdown autour d'une réponse initiale courte, puis de quatre à six questions utiles. Donner une démarche reproductible, un tableau de décision ou de contrôle quand il clarifie le sujet, quelques questions fréquentes et un lien de contact adapté. Le français professionnel du profil utilise le vouvoiement.

Avant publication, contrôler chaque affirmation, l'orthographe, les liens, l'absence de doublon et de note interne. Ne pas inventer de statistiques pour rendre le guide convaincant. Une information non vérifiable est reformulée prudemment ou retirée. Si elle est indispensable, arrêter avec le blocage exact. Le guide prépare une décision ; il ne promet aucun résultat commercial ou technique universel.
